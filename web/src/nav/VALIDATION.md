## 수정한 오류

- 실시간 위치 갱신이 멈춰도 마지막 위치로 안내하던 문제: 1.5초 만료와 `tracked: false` 처리. 정적 시작점 선택에는 만료를 적용하지 않는다.
- 명시적으로 다른 좌표계/지도에 속하는 입력 수용: 입력 검증과 검증된 위치 이벤트 `nav:location` 사용.
- 현장 안내와 D 안내의 상태 충돌: 현장 모드에서는 D의 목적지 요청·위치 입력·복귀 경로 출력을 중단한다. 경보 상태 자체는 기억한다.
- 지도에서 경로 모서리를 곡선으로 둥글려 표시하던 문제: 계산된 경로 점을 지나는 직선 구간으로 표시한다.
- 새 목적지 요청의 취소 이벤트가 잘못된 목적지를 가리키던 문제: 취소에는 이전 목적지와 경로 ID를 담는다.
- 취소된 계산의 늦은 오류가 새로운 경로를 중단할 수 있던 문제: Worker 오류의 요청 ID를 확인한다.
- 연속해서 같은 이유로 막히면 HUD에 이전 목적지가 남을 수 있던 문제: 새 요청 전 이전 경로 상태를 명시적으로 종료한다.
- 지연되거나 중복된 위치 샘플이 유효 시간을 연장하던 문제: 샘플 시각 기준 만료와 중복 시각 거부.

## 남아 있는 오류와 발생 조건

아래는 이번 기준 버전에서 확인한 통합 공백 또는 코드상 재현 가능한 문제다. 다른 담당 폴더를 고치지 않았으므로 전체 시연이 완성됐다는 의미는 아니다.

| 항목 | 발생 조건과 영향 | 연결·수정 위치 |
|---|---|---|
| 센서 장애물이 화성 경로에 반영되지 않음 | 스캐너는 지역 좌표를 보내지만 화성 지도 좌표로 등록하는 연결이 없다. D는 불일치 입력을 거부하고 미확인 비용 3배를 유지한다. `frameId`만 임의로 붙이면 위치가 틀릴 수 있다. | A/B의 관측 등록 → D `updateHazard` |
| 현장 경로가 벽을 통과할 수 있음 | 현장 계산기의 시작/목표 중 하나가 격자 밖이면 내부의 알려진 장애물도 검사하지 않고 직선을 반환한다. | `field/planner.js`의 범위 밖 처리 |
| 현장 계산기가 미확인 구역을 과도하게 선택 | 현장 기본 비용은 1.4배이고, 단순화가 가중 비용을 보존하지 않는다. D의 3배 규칙과 별개다. | `field/planner.js`의 비용·단순화 |
| 추적 복구 때 위치가 기지로 이동 | 위치 제공자의 `startTracking()`이 추적 복구 때 초기 기지에 다시 고정한다. D의 만료 처리는 안내를 멈출 뿐, 잘못 복구된 좌표를 알아낼 수 없다. | `field/index.js`의 anchor 복구 |
| 시연 중 도착 판정을 건너뛸 수 있음 | 현재 화성 모드의 기본 이동 배율은 100배이고 위치 전송은 200 ms 간격이다. 예를 들어 실제 0.1 m 이동은 지도 10 m가 되어 2 m 도착 범위를 건너뛸 수 있다. | B의 시연 위치 입력과 D 도착 규칙의 통합 검증 |
| 짧은 통로나 작은 장애물에서 경로가 과도하게 막힘 | 화성 격자가 4 m이므로 장애물과 교차한 셀 전체가 제외된다. 정밀 관측의 통과 가능성을 모두 표현할 수 없는 현재 전역 격자의 한계다. | 전역 경로와 정밀 국소 회피의 연결 |
| 온도 하강 후에도 심각 경보 유지 | 기준 main에는 경보 완화 문제가 있으며 수정은 별도 PR #8에서 진행 중이다. 이번 D 테스트는 합성 경보 이벤트를 사용했다. | E의 센서/경보 처리 |

연동 시 `ts`를 넣는다면 `Date.now()`와 같은 Unix 밀리초를 사용해야 한다. `performance.now()`를 전달하면 오래된 샘플로 거부된다. 위치 이벤트에 좌표계 정보가 없는 경우는 기존 B 계약과의 호환을 위해 지도 미터로 해석하므로, 제공자의 잘못된 단위를 자동으로 판별하지는 못한다.

## 실제 기기에서 확인할 항목

1. 정상 보행 중 위치 이벤트가 계속 도착하는지, 추적 상실 시 안내가 멈추고 복구 시 올바른 지도 위치를 유지하는지.
2. 등록된 장애물의 생성·이동·제거가 실제 경로와 지도에 반영되는지.
3. 목적지 도착·일반 복귀·위험 복귀가 HUD 및 음성과 일치하는지.
4. Quest에서 손 추적·깊이 데이터·메뉴·마이크·Jetson/온도 센서 연결이 동작하는지.
5. B의 통합 PR 병합 후 같은 파일 변경을 반영하고 자동 테스트를 다시 실행할 것.
